SALES +1 ／ 責任者日報 v3（確認用）

責任者日報を「報告書」から「今日の打ち手を回す道具」に変える

2026年10月9日（金）時点 ／ v3：振り返りを長さごとの3つの輪（毎日・毎週・毎月）に整理し、昨日の打ち手の「できた／できなかった」と要因、明日の打ち手の「狙い」を追加。v2：日々のMVPの選定と、月末の組織MVPの報告を追加（本人の要望）。v1：今の責任者日報（Microsoft Forms の回答 1,862件）の分析と、本人と決めた新しい形を確認するための資料。決まったことと、まだ決まっていないことを分けて示す

結論

今の責任者日報は1年以上続いていますが、1人1日約1,000字を書いても返事の流れがなく、半分近くが数字やほかの記録の書き写しです。新しい形では、数字や記録はアプリが自動で並べ、責任者が夜に書くのは「要因」「明日の打ち手」「今月のテーマのひとこと」の3つと、日々のMVPを選ぶことだけにします。朝は書きません。

今、1日に書く量約1,000字朝 約550字＋夜 約470字
新しい形で書く量約150字夜の3つだけ（見込み）
書く欄の数23 → 3朝13・夜10 → 夜3＋打ち手の結果とMVPを選ぶ
返事の流れ週1回AIの要約に直属の上席がひとこと
この資料で何度も出てくる言葉

打ち手：責任者が「誰に・何を・なぜ」するかを決めた行動（用語集）。今月のテーマ：責任者が1か月で伸ばすマネジメントの課題を1つにしぼったもの（用語集）。

2良いところと直したいところ：習慣は根づいているが、返事がなく判断が埋もれている

良いところ直したいところ

夜のチェック（30コール・リストの確認）は×も正直についている（3〜4割）振り返りがばらばら：「できなかったこと」の38%が自分の数字の話で、毎日の課題が一貫しない

PART 2

新しい形

3目的：上への報告ではなく、責任者が振り返って自分と組織を伸ばすため

目的にすること 決定

  • 責任者が自分のマネジメントを回す（今日の稼働を振り返り、明日の打ち手を決める）
  • メンバーの状態を共有して手を打つ
  • その結果として、組織の数字を伸ばす

目的にしないこと

  • 上への報告（代表が組織の状況をつかむのは、ダッシュボードと週1回の要約で行う）
  • 数字の報告（数字はアプリが自動で出す）
図の見方
  • 左が目的、右が目的にしないこと
ポイント（要点）
  • 目的が「振り返り」なので、書く欄は考えたことだけにしぼれる
  • 代表の把握は日報ではなく、数字の画面と週1回の要約で行う

41日の流れ：夜に決めた打ち手が、翌日の打ち手になる

朝は書きません 決定。夜に書く3つが、翌日の動きにそのままつながります。

図の見方
  • 右回りに進む。上の濃紺が、責任者が書く唯一の場面
  • 業後に数字がそろってから夜の日報を書くので、その日の結果で振り返れる
ポイント（要点）
  • 朝と夜の2回、同じ日の結果を振り返っていたのを、夜の1回にまとめた
  • 夜の「明日の打ち手」が、翌日の打ち手としてそのまま表示される
  • 未達の一覧は、まとまり4で決めたもの（承認の直後に、リーダーごとに出る）

4-23つの輪：毎日は「やったか」、毎週と毎月で「効いたか」を見る

今のFormsの振り返りは、形はPDCAですが、評価が「やったかどうか」で止まっていました。一方で、1日では数字が偶然で大きく動くので、毎日「効いたか」を評価するのは重く、ぶれます。そこで、長さごとに3つの輪を重ねます 決定。

長さ回し方責任者がすることアプリがすること
毎日OODA＋仮説：数字と記録を見て、明日の打ち手を決める夜：昨日の打ち手ごとに「できた／できなかった」を選び、できなかったときは要因を必ず書く。明日の打ち手に「狙い（何がどう変わるはずか）」を1行つける数字・未達の一覧・記録を並べる。前の夜の打ち手を今日の打ち手として出す
毎週KPT・仮説検証：打ち手が狙いどおり効いたかをまとめて見る直属の上席の返事を読み、翌週の打ち手に生かすAIが1週間の打ち手を「狙いどおり変わったか」で整理し、続けること・問題・次に試すことにまとめる。打ち手の実行率（できた割合）とできなかった要因の傾向も出す
毎月PDCA・経験学習：今月のテーマで自分の成長を見る月末：今月のテーマの達成／未達と、わかったことを書く。組織MVPを報告するテーマの進み具合と、日々のMVPのまとめを並べる
図の見方
  • 上から、毎日・毎週・毎月の3つの輪。下の輪ほど長い期間で「効いたか」を見る
  • 右の2列は、責任者がすることと、アプリが代わりにすること
ポイント（要点）
  • 毎日は「やったか」と「できなかった要因」だけ。負担を増やさずに、打ち手を決めっぱなしにしない
  • 打ち手に「狙い」を書いておくと、週の要約で「狙いどおり変わったか」を確かめられる。評価が「やったかどうか」で止まらない
  • 数字の効果は、ロープレや週間教育と同じく、ある程度の期間で見る

7-2日々のMVP：数字だけでなく、稼働姿勢と周りへの良い影響で選び、月末の組織MVPにつなげる

会社のMVPは、数字だけでなく日々の稼働姿勢で決めています（本人より）。そこで夜の日報で毎日1人を日々のMVPとして選び、月末に責任者が組織のMVPを報告するときの材料にします 決定。今のFormsの「印象的だったメンバーの行動・成長」の欄（934件すべてで記入）を、MVPとしてはっきりさせる形です。

1毎晩：1人を選ぶ理由の種類（稼働姿勢・周りへの良い影響・数字）とひとこと。該当なしも可
2月末：自動でまとまる選ばれた回数・理由の種類の内訳・ひとことの一覧
3責任者が組織MVPを報告まとめを見て1人選び、理由を書く
4上席と代表が見るメンバーへの知らせ方は今の会社のやり方のまま

8週1回の要約と返事：毎日ではなく週1回、直属の上席がひとこと返す

今は日報は読まれていますが、返事はしていません。毎日返すのは負担が大きいので、AIが1週間分を責任者ごとに要約し、直属の上席がそれを読んでひとこと返します。

図の見方

  • 下の小さい字は、要約の中身と、返す人の決まり
ポイント（要点）
  • 要約は、打ち手が狙いどおり変わったかを「続けること・問題・次に試すこと」（KPT）の形でまとめる
  • 責任者は今4人なので、要約は週に4件ほど。返す人の負担は小さい
  • 日々の様子を知っている直属の上席が返すので、ひとことが具体的になる 決定
  • AIは要約を書くだけで、数字の計算はプログラムが行う（AIの要約）

  • 返す人は、週1回の要約と同じ直属の上席

確認

10なくすもの：書き写し・形だけのチェック・二重の振り返り

なくすもの理由かわりに
数字の書き写し（見込み・訪問・受注・達成率）メンバーの入力やKPIから自動で出せる。書き方が人ごとにばらばらで集計できない夜の画面に自動で並ぶ
朝のチェック4つ98%以上が○で情報になっていない日報や記録を開いたかは、アプリの記録で自動でわかる
朝の報告朝と夜で同じ日の結果を2回振り返っていた前の夜の「明日の打ち手」を使う
「できたこと・できなかったこと」の欄毎日ばらばらで一貫しない「要因」と「今月のテーマのひとこと」
朝の行動内容・メンバーへの言及の欄ロープレ・研修・部下メモと二重になるそれぞれの記録から自動で並ぶ。「印象的だったメンバー」は日々のMVPになる
図の見方
  • 1行が1つのなくすもの。右の列が、そのかわりになるしくみ
ポイント（要点）
  • なくすものは「考えなくてよい部分」。考える部分（要因・打ち手・テーマ）は残す

責任者日報のしくみ

打ち手
課題に対して、誰に・何を・なぜするかを決めた具体的な行動。
夜に「明日の打ち手」を書くと、翌日の「今日の打ち手」として表示される。
今月のテーマ
責任者が1か月で伸ばすマネジメントの課題を、1つにしぼったもの。結果ではなく行動で書く。
「メンバー全員と週1回ロープレする」など。記録で数えられれば進み具合が自動で出る。
未達の一覧
本人が立てたKPIの目標に届かなかったメンバーを、責任者ごとにまとめた一覧。
業後の取り込みと承認の直後に出る（まとまり4で決定）。責任者は「対応済／不要だった」と理由を残す。
直属の上席
その人のすぐ上の立場の人。
リーダーなら担当のMGR、MGRなら代表。週1回の要約に返事をし、「返事がほしい」の質問に答える。
AIの要約
1週間分の日報と記録をもとに、AIが短くまとめた文章。数字の計算はプログラムが行い、AIは計算済みの数字を使う。
力を入れたメンバーとその変化、打ち手のあとの数字の動きを書く。
OODAウーダ
見る（Observe）→ 状況をつかむ（Orient）→ 決める（Decide）→ やる（Act）の順に、素早く回す考え方。計画より、目の前の状況への対応を重んじる。
毎晩、その日の数字と記録を見て、明日の打ち手を決める。
仮説・狙い
「こうすれば、こう変わるはず」という見込み。結果と比べて、当たったかを確かめる。
明日の打ち手に「狙い：総を1日150件に」のように1行つける。
KPTケプト
続けること（Keep）・問題（Problem）・次に試すこと（Try）の3つで振り返る型。
週1回のAIの要約を、この形でまとめる。
経験学習経験学習モデル
経験 → 振り返り → 教訓にする → 試す、の流れで人が育つという考え方。
今月のテーマの月末の振り返りで、わかったことを書く。
日々のMVP
その日に最も良い稼働をしたメンバーを、責任者が1人選んだもの。数字だけでなく、稼働姿勢や周りへの良い影響も理由にする。
月末に自動でまとまり、責任者が組織のMVPを報告するときの材料になる。
Microsoft Forms
Microsoft 365 のアンケート作成の道具。回答はExcelに書き出せる。
今の責任者日報はFormsで朝と夜に送っている。

数字とほかの記録

あるべき
月の経過に合わせて、今日までに本来届いているべき量。
「目標に対して29%、あるべきに対して36%」のように、月の目標と並べて使う。
見込みのランク
見込み（またかけるべき相手）を、確度でS・A・B・C・ランク無しに分けたもの。
今はメンバーが業後に別のExcelに入力している。アプリでの扱いは未決。
読込アポ
見込みの中で、いちばん確度が高く「アポになる」と読んでいる相手。
「読込アポ 5件 → 3件」のように、何件アポになったかを翌朝に書いていた。
部下メモ
上席が部下に気づいたこと・指導したことの記録。本人には見せない。
気になった・伸びたメンバーは、日報ではなく部下メモに書き、日報に自動で並ぶ。
練習中のテーマ
ロープレで、その人が今身につけようとしているテーマ。アポと営業で1つずつまで。
気になったメンバーを選ぶと、夜の画面に出る。
週間教育
問題 → 原因 → 行動 → 振り返りを週ごとに回す育成の記録。効果は2週間で判定する。
気になったメンバーを選ぶと、その人の今週の行動が夜の画面に出る。
