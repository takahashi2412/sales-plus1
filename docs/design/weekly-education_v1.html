結論

「数字を見て、問題・原因・行動を決め、実行して検証し、次の周につなぐ」という今の週間教育の型は正しく、アプリでもそのまま使います。直すのは、数字の意味をそろえること、問題・原因・行動を1つずつつなぐこと、効果を偶然と区別して判定すること、うまくいったやり方をチームに広げることの4つです。

PART 1

今のExcel

1今の流れ：検証から出た次の問題が、次の周の出発点になる

Excelの「記入例」のシートは、1つの取り組みを2周回した例です。1周目の検証で見つかった問題が、2周目の原因として引き継がれています。下は記入例を短く言いかえたものです。

図の見方
  • 上の段が1周目、下の段が2周目。箱はExcelの列（欄）
  • 箱の中の小さい字は、記入例の中身を短く言いかえたもの
  • 濃紺の矢印が、1周目の「次の問題」を2周目の「原因分析」に引き継ぐ流れ
ポイント（要点）
  • 1回で終わらず、検証から次の手を出して回し続ける形になっている。これがこの型のいちばん良いところ
  • アプリでは、この「引き継ぎ」をボタン1つでできるようにする（セクション7）

2正しいところ：6つはアプリでもそのまま活かす

数字から始まる

まず数字を見てから問題を探す。感覚で決めない

問題 → 原因 → 行動の順

設計書の週間教育の型と同じ。原因を飛ばして行動を決めない

検証を数字でする

「アポ率0.8%」「時間切り50%」のように、結果を数字で書く

次の周につなぐ

検証から次の問題を出し、次の周の出発点にする（セクション1）

行動が数えられる

「ロープレを3回」のように、やったかどうかを確かめられる

うまくいったら印をつける

再現化の〇。良いやり方を残そうとしている

図の見方
  • 1枚が1つの良い点。小さい字はその理由
ポイント（要点）
  • 型を変える必要はない。メンバーと上席は、今と同じ考え方でアプリを使える
  • アプリが補うのは、手で書くと崩れやすいところ（数字の意味、つながり、記録の残し方）
PART 2

改善したいところ

3改善点8つ：手で書くと崩れやすいところを、アプリの仕組みで支える

#今のExcel起きることアプリでは
1「アポ率」と書いてあるが、ア÷総（ア率）かア÷オ（ア/オ）かわからない。期間も書いていない人によって違う数字を比べてしまう狙うKPIを6つから選ぶ。前後の数字はKPIから自動で出す
21週間で、本人の数字だけを見て効果を決めている偶然の上がり下がりを「効果あり」と思ってしまう（セクション4）前後2週間で、チーム平均と比べて判定する
3問題3つ・原因3つ・行動1つ。問題の欄に問題でないこと（見込みが増えた）も入るどの原因に効かせる行動か、わからない（セクション5）問題1つ → 主な原因1つ → 行動1つ。気づいた数字は「数字把握」に分ける
4自分で測った数字（切り返しからの時間切り率など）を検証に使っている電話システムのCSVにないので、判定には使えない「補助の数字」の欄（任意）に記録する。判定には使わない
5ロープレなどの実施回数を手で書く（実際の記録では空欄）行動を実行したかがわからないまま検証してしまうロープレの記録と自動でつなぎ、回数を数える
6再現化の〇が本人の記録で終わるうまくいったやり方が、チームに広がらない「効果あり」で上席がOKしたら勝ちパターンとして共有する（セクション8）
7上席・担当・項目の選択リストが壊れている（参照先が消えている）。日付の欄に日付と期間がまざる。上席コメントに取り組みと関係なさそうなメモ名前の書き方がゆれ、期間で集計できない上席・担当は名簿から選ぶ。開始日と判定日を分ける。コメントは週ごとのふり返りに書く
8過去の行が残っていない（2〜57行目が空）過去の取り組みと効果をふり返れない記録は消さずに残す（論理削除）。カルテに時系列で並ぶ
図の見方
  • 1行が1つの改善点。左から「今」「困ること」「アプリでの直し方」
  • 2・3は、次のセクション4・5で図にして説明する
ポイント（要点）
  • どれも書く人の努力の問題ではなく、Excelの仕組みでは防ぎにくいこと
  • アプリでは「選ぶ」「自動で出す」「自動で数える」を増やし、手で書くのは考える部分（問題・原因・行動・ふり返り）だけにする

4偶然と区別できない：記入例の上がり方は、何もしなくても起こりうる幅の中

記入例では「アポ率0.5% → 0.8% → 1.3%」と上がっています。ところが、KPIの見本で計算すると、ア率は何もしなくても1週間で1.4ポイントくらいは上下します。コインを少ない回数だけ投げたときと同じで、短い期間では偶然の揺れが大きいためです。

図の見方
  • 横はア率（％）の目盛り。丸が記入例の3つの数字。差はポイントで表す（0.5%→0.8%は0.3ポイント）
  • 色のついた帯が、取り組みがなくても1週間で動く範囲（偶然の動き）
  • 点線より右に出たら「偶然ではなさそう」と言える
ポイント（要点）
  • 記入例の取り組みが効かなかった、という意味ではない。今の書き方では、効いたかどうかを見分けられない、という意味
  • アプリでは、前後2週間で比べ、チーム平均の上がり分も引いて判定する（設計書のセクション8）
  • 偶然の幅は、KPIの見本（1人分・36稼働日）から計算した値

51対1のつながり：問題・原因・行動を1つずつにすると、検証できる

実際の記録は、問題が3つ、原因が3つ、行動が1つでした。どの原因に効かせる行動なのかがわからないと、結果が出ても何が効いたのか言えません。下は、実際の記録をもとにした架空の例です。

図の見方
  • 左が今の記録。点線は「どれとどれがつながっているか、はっきりしない」ことを表す
  • 右がアプリの形。上から下へ1本でつながる
ポイント（要点）
  • 1本でつながっていれば、2週間後に「オ率が上がったか」を見るだけで、この行動が効いたかがわかる
  • 問題がいくつもあるときは、いちばん大きいものから1つずつ回す。残りは次の周に回す
  • 「見込みが増えた」のような気づきは、問題ではなく数字把握の欄に書く
PART 3

アプリの形

6毎週と2週間の流れ：毎週は「実行できたか」、2週間で「数字が動いたか」を見る

今の毎週の面談はそのまま続けます。毎週は行動を実行できたかをふり返り、数字の効果は2週間たった時点でシステムが判定します決定。丸数字は10の段階の番号です。

図の見方
  • 横は時間（左が登録の日、右が2週間後の判定の日）。上の帯は人がすること、下の帯はシステムがすること
  • 縦の矢印は、システムが出した数字や判定を人が見て使うこと
ポイント（要点）
  • 毎週の面談の習慣は変わらない。変わるのは、毎週「数字の効果」を決めないこと
  • 人が手で書くのは、考える部分（問題・原因・行動・ふり返り）だけ。数字・回数・判定はシステムが出す
  • ⑨の次の問題は、次の周の出発点として引き継がれる（セクション1の流れと同じ）

7画面のイメージ：灰色の欄は自動、白い欄だけを人が書く

  • 上席コメントは、毎週のふり返りの中に書く（取り組みと関係のないメモが入らないように）

8勝ちパターンの共有：1人の「効果あり」を、チームとAIの財産にする

今は再現化の〇が本人の記録で終わっています。アプリでは、効果があったやり方を「勝ちパターン」として集め、同じ問題をかかえる人が使えるようにします。

図の見方
  • 左から右へ。判定で「効果あり」になり、上席がOKしたものだけが勝ちパターン集に入る
  • 右の2つが、勝ちパターンの使い道
ポイント（要点）
  • 判定（数字）と上席の確認（中身）の両方を通ったものだけを集める。偶然うまくいったものを広げないため
  • AIは、根拠のある提案ができるようになる（「同じ問題で効果があったやり方」）
  • 誰のやり方かを名前つきで見せるか、名前を出さずに見せるかは確認待ち案

数字と判定

狙うKPI
週間教育の取り組みで、上げようとしている数字。効果の判定はこの数字で行う。
実率・オ率・見率・ア率・ア/オ・総（1日あたり）の6つから選ぶ。1日全体の数字だけ。
ポイントpt
％どうしの差を表す単位。0.5%から0.8%への変化は「0.3ポイント上がった」。
効果の判定の線や、偶然の幅はポイントで表す。
偶然の動き
取り組みとは関係なく、毎日の条件の違いで数字が上下すること。期間が短く、数が少ないほど大きくなる。
ア率は、何もしなくても1週間で1.4ポイントくらい動く（KPIの見本から計算）。
判定
取り組みの前後2週間の数字を比べ、チーム平均の上がり分を引いて、効果があったかをシステムが決めること。
効果あり／変化なし／逆効果の疑い／判断できない の4つ。設計書のセクション8。
補助の数字
電話システムのデータにはない、自分で測った数字。判定には使わないが、改善の手がかりとして残す。
切り返しからの時間切り率、冒頭で断られた割合など。
