PART 2

サイトの中の形：画面・箱・データ・フォルダ

3画面のツリー：1つのサイトの中に、ホームと3つの区分

使う人から見たサイトの形です。ログインするとホーム（今日やること）が開き、左のメニューで各画面へ移ります。

  • SALES +1（1つのサイト・Microsoft 365 でログイン）
    • ホーム（今日やること）役割ごとに、やることを件数つきで
    • 書く（7画面）
      • 一般日報メンバー・業後（受注・見込み・週の約束も）
      • 責任者日報リーダー・MGR・夜
      • 部下メモ上席が書く・本人に見せない
      • ロープレ1回1テーマ・○△×
      • 研修の記録参加者は複数
      • 週間教育問題→原因→行動・2週間で判定
      • KPIの目標（月初）本人が立てる・逆算は自動
    • 見る（5画面）
      • ダッシュボードチーム一覧・行を押すとカルテ
      • メンバーカルテ1人の数字と記録が1画面に（中心の画面）
      • 未達の一覧業後・対応を記録
      • AIレポート本人版・指導版（月曜）
      • トーク一覧確認待ち→試行中→標準
    • 管理（5画面・管理者の権限で使う）
      • CSV取り込み・承認業後に1回
      • 名簿・所属・MGRの担当異動は履歴を残す
      • 権限トーク責任者も・代表と管理者
      • 設定値判定の線・分類の言葉など
      • 監査ログ誰が・いつ・何を変えたか
濃紺 土台の画面点線 集める画面（ほかの業務の記録を読む）白 業務の箱の画面
図の見方
  • いちばん上がサイト全体。線をたどると、区分 → 画面の順に枝分かれする
  • 箱の右の小さい字は、その画面のひとこと説明
ポイント
  • この形は、今までの設計（設計書9章）と同じ。作り方が変わっても、使う人の画面の並びは変わらない
  • 点線の4画面（ホーム・ダッシュボード・カルテ・AIレポート）は集める画面。ほかの業務の記録を読んで1か所に並べる

5データのつながり：すべての箱は、土台の名簿（member_id）でつながる

真ん中が土台、まわりが業務の箱です。実線は「この人の記録」として名簿とつながること、点線は集める画面が読むことを表します。

図の見方
  • 中央の濃紺が土台。まわりの白い7つが業務の箱。下の点線の箱が集める画面
  • 集める画面から土台への矢印は、土台を通してすべての箱の記録を読むことを表す
ポイント
  • どの業務で書いた記録も member_id で同じ人につながるので、カルテに1人の記録が全部集まる。これが SALES +1 の中心の価値
  • だれが読めるかは、土台の権限で決まる（行ごとの読み書きの決まり）。業務の箱ごとに権限を作らない

6フォルダのツリー：アプリのフォルダの中も、土台と業務の箱に分ける

作る側のファイルの置き場所です。案 業務のフォルダの名前は例で、それぞれの計画ファイルを作るときに決めます。

  • C:\Workspace\apps\
    • sales-plus1\元のフォルダ（本線）。Claude Code が使う
      • src\サイトのプログラム
        • foundation\土台：ログイン・名簿・権限
        • features\業務の箱（1業務＝1フォルダ）
          • roleplay\ ・ kpi\ ・ memo\ ・ daily-report\ ・ training\ ・ manager-report\ ・ ai\名前は例
          • home\ ・ dashboard\ ・ karte\集める画面（名前は例）
      • supabase\migrations\表と権限の SQL（マイグレーション）
      • tests\guard\守りのテスト（Claude Code の担当）
      • fixtures\架空データ
      • docs\design（設計書・図解）・tasks（計画ファイル）・reports（報告書）
      • samples\実名の見本。Git の外（GitHub に上がらない）
      • .env鍵。Git の外
    • sales-plus1-worktrees\作業用フォルダの置き場所。Antigravity が使う
      • foundation\土台を作るときの作業用フォルダ（次に用意する）
      • 〈計画の名前〉\ロープレなど、計画ごとに用意して、取り込んだら片づける
濃紺 土台点線 集める画面橙 案（名前は例）点線の灰 Git の外・一時的なもの
図の見方
  • いちばん上が Workspace の apps フォルダ。その中に、元のフォルダと作業用フォルダの置き場所が並ぶ
  • 箱の右の小さい字は、そのフォルダの中身と、だれが使うか
ポイント
  • 4の箱の分け方が、そのまま src\ の中のフォルダの分け方になる。日報を直すときは features\daily-report\ の中だけを触る
  • 作業用フォルダは、元のフォルダのコピーのようなもの。samples\ と .env は Git の外なので、作業用フォルダには入らない（.env だけ Claude Code が写す）
PART 3

作り方：どの順番で、どう作るか

7作る順番のチャート：区切りを進むごとに、表と画面がそろっていく

9つの区切りを左から順に作ったとき、できあがる表と画面の数（それまでの合計）の目安です。4の箱の分け方と、作る順番の表（設計書13章）から数えました。日付はまだ決めていません。（区切りの名前は、同じ時期に作るもののまとまりで、画面のまとまりではありません。例：「KPI・部下メモ」は、KPI の画面と部下メモの画面を同じ時期に作るという意味で、サイトでは別々の画面です）

図の見方
  • 横が作る順番、縦が数。濃い棒が表、薄い棒が画面。数は、その区切りまでに作ったものの合計
  • 棒が伸びない区切り（カルテ第1版の表、自動化）は、新しい表を作らず、今ある表を読む・使う区切り
ポイント
  • 表は前半（土台〜KPI・部下メモ）で6割（23／37）がそろう。カルテ第1版の節目で、リーダー層が記録を書いて見られる形になる
  • 画面は、管理の2つの区切りが決まると18になる。この2つは、名簿を直す・権限を与える画面なので、本物のデータを入れる前（カルテ第1版の節目まで）に要る

81つを作る流れ：決める → 計画 → 別のフォルダで作る → 確かめる → 本線へ

図の見方
  • 左から右へ、1つの区切りを作る流れ。濃紺がご自身の番、薄い青が作る所
ポイント
  • ご自身がするのは、1で選ぶこと・3の前に作業用フォルダを Antigravity で開いて計画を渡すこと・4で画面を確かめて OK を出すこと・GitHub に送ること
  • 12の手順の図は 制作の手順の3章、2つのフォルダの図は 4章

9並列の流れ：表は先に1本で作り、画面を2本同時に作る

図の見方
  • 左から右へ時間が進む。真ん中の薄い青の2本が、同時に作る並列の部分（ロープレの区切りの例）
ポイント
  • 表と共通の部品は、2本が同時に触るとぶつかるので先に1本で作る。画面は業務の箱が分かれているので、2本同時でもぶつかりにくい
  • 速くなるのは「作る」だけ。確かめるのは1本ずつなので、2本までにしている。詳しい決まりは 制作の手順の6章

この資料で使った言葉

本文の点線の下線から移動してきた場合、その言葉の枠が濃紺で囲まれます。「この案件での例」は、SALES +1 での具体例です。

サイトの中の形

土台
どの業務も共通で使う部分。1つにまとめておくと、直すときに1か所で済む。
名簿・ログイン（Microsoft 365）・権限と、設定値・監査ログ・一覧の表。最初の区切りで作り、あとのすべての業務が使う。
業務の箱モジュール
1つの業務に必要な表・画面・プログラムを、ほかの業務と分けてまとめたもの。箱の中を直しても、ほかの箱に響かない。
ロープレ・KPI・部下メモ・一般日報・週間教育・責任者日報・AI の7つ。それぞれ src\features\ の中に1つのフォルダを持つ。
集める画面
自分の表を持たず、ほかの業務の記録を読んで1か所に並べる画面。
ホーム・ダッシュボード・メンバーカルテ（AIレポートもほかの記録を読む）。カルテ第1版と「責任者日報・集める画面」の2回だけ作る。
member_id
名簿の中で、1人に1つ決まる番号。名前が同じ人がいても区別できる。
どの業務の表にも入っていて、カルテに1人の記録を集める鍵になる。
行ごとの読み書きの決まりRLS
データベースの表の1行ずつについて、だれが読めるか・書けるかをデータベースそのものに決めておく仕組み。
メンバーは自分と同じチーム、MGR は担当チームだけ、など。土台で1回作り、すべての表に効かせる。
マイグレーション
データベースの表の作り方や変え方を書いた SQL のファイル。順に流し込むと、同じ表をいつでも作り直せる。
supabase\migrations\ に置く。2本が同時に変えるとぶつかるので、並列にしない。
架空データfixtures
画面やテストを確かめるための、作り物のデータ。
「メンバーA」のような架空の名前だけ。fixtures\ に置き、本物の名前は使わない。
守りのテスト
絶対に崩してはいけない決まりを、プログラムが毎回自動で確かめるテスト。
tests\guard\ に置く。今は権限のテスト。作る係（Antigravity）は変えてはいけない。

作り方

区切り
作る順番の1つのまとまり。番号ではなく中身の名前で呼ぶ。同じ時期に作るもののまとまりで、画面のまとまりではない（「KPI・部下メモ」の KPI と部下メモは、サイトでは別々の画面）。
土台・ロープレ・KPI・部下メモ・カルテ第1版・一般日報・週間教育・責任者日報・集める画面・AI・自動化の9つ。
並列
複数の作業を同時に進めること。
Antigravity を2本まで同時に動かし、別々の画面を作らせる。表と共通の部品は並列にしない。
作業用フォルダワークツリー
同じアプリのファイル一式を、別のフォルダにもう1つ開いたもの。フォルダが違うので、同時に作業してもぶつからない。
