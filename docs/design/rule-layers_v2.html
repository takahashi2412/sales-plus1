2決まった作業の流れ：本線はレビューの後にだけ変わる

sales-plus1だけGitを使います。Antigravityは作業用の枝（ブランチ）でコミットまで行い、本線（main）とGitHubには触れません。

  1. 1Claude Code
    計画ファイルを書く
    docs/tasks/plan_内容_v1.md。守らせたいルールもここに書く
  2. 2Antigravity
    作業用ブランチで実装・コミット
    /plan @docs/tasks/… で受け取る。結果は docs/reports/ にも残す
  3. 3Claude Code
    本線との差分をレビュー
    守りのテストが変わっていないかを必ず見る
  4. 4あなた
    OKを出す
    ここを通らないと本線は変わらない
  5. 5Claude Code
    本線に取り込み、push
    pushは毎回確認を取ってから。--force は使わない
ポイント

2つのツールは順番に使います（Antigravityは「Local」で作業）。同じフォルダで同時に作業させません。

2台の受け渡し

sales-plus1は手でコピーせず、作業前に pull、区切りで push します。

4破ってはいけないことは、仕組みで止める

ルールファイルはAIへのお願いです。読み飛ばされると守られないので、事故につながるものはGitや設定で強制します。

守りたいことファイルだけだと仕組みで止める方法状態
本人版レポートに部下メモを渡さないAIが忘れると漏れるテストで自動確認する。テストは頭脳側が持ち、Antigravityは変更しない。レビューで変更がないか見るこれから
APIキーは .env に置くキーがコードに書き込まれる.gitignore で .env をGitに入れない（見本の .env.example だけ入る）設定済み
実名データ・通話録音を置かない本物のデータが上がるExcel・CSV・録音・PDF・Word・zipをGitに入れない。本物の見本データの samples/ はフォルダごと入れない。開発用の架空CSVは fixtures/ だけ許可設定済み
レビュー前に本線を変えない確認前に本番の流れに入るAntigravityは作業用ブランチでコミットまで。取り込みとpushはClaude Codeが確認後に行うルール化済み
削除・pushの前に確認自動で実行されるAntigravityの設定でコマンドを毎回承認にする（Request Review）これから
赤は1画面1〜2か所画面ごとに色がばらつく色と余白をコードの1か所に部品として定義し、それ以外の色を使わないこれから

5AGENTS.mdを作る前に確かめる3点

  1. 1
    Antigravity（2.0アプリ）がAGENTS.mdを読むか
    確かめ方：見本のAGENTS.mdを置き、Antigravityに「読み込んでいるルールファイルをすべて挙げて」と聞く
    v1の「バージョン1.20.3以上かを見る」は誤り。1.20.3は旧IDE側の番号で、2.0アプリには当てはまらない
  2. 2
    上の階層のルールファイルを読むか
    確かめ方：1と同じ質問で、C:\Workspace のファイルが挙がるかを見る
  3. 3
    日本語を含むパスで、@による読み込みが動くか
    確かめ方：Claude Code側で @~/.gemini/GEMINI.md を試す。実例として、Claudeアプリのターミナルパネルは「髙」を含むパスで部品を読み込めず、動かなかった
