## 4. 仕様

### 切り替え先（引数はこの5つだけ）
- 引数がない・知らない引数のときは、環境変数の確かめとデータベースへの接続より前に使い方を出し、終了コード1で終える（データベースには接続しない）
| 引数 | 役割（members.role） | 所属（member_affiliations） | MGR の担当（mgr_assignments） | 権限（permissions） | 画面での見え方の目安 |
|---|---|---|---|---|---|
| `ceo` | `ceo` | なし | なし | なし | 全員（元に戻す） |
| `leader` | `leader` | 架空チームA（開始 2025-04-01、終了なし、拠点「架空拠点A」） | なし | なし | 架空チームAのリーダー |
| `member` | `member` | 架空チームA（同上） | なし | なし | 架空チームAのメンバー |
| `mgr` | `mgr` | なし | 架空チームA（開始 2025-04-01、終了なし、`assigned_by` は空） | なし | 架空チームAの担当MGR |
| `talk-owner` | `member` | 架空チームB（開始 2025-04-01、終了なし、拠点「架空拠点B」） | なし | `talk_owner`（`granted_by` は空、取り消しなし） | 架空チームBのメンバーで、トーク責任者 |

- チームは、土台の架空データ（`fixtures/foundation/data.mjs`）の「架空チームA」「架空チームB」を名前で探す。見つからなければ「先に `npm run fixtures:load` を流してください」と出して何もせずに終える

### 切り替えの手順
1. 管理用の鍵（`SUPABASE_URL`・`SUPABASE_SERVICE_ROLE_KEY`。`.env` から `node --env-file` で読む）で接続する。`DEV_LOGIN_EMAIL` もなければ止める
2. 名簿（members）から、名前が `テスト代表`（`fixtures/foundation/data.mjs` の `TEST_CEO_NAME`）で、かつメールが `DEV_LOGIN_EMAIL` と同じ（大文字・小文字を区別しない）行を探す。ちょうど1行でなければ、何もせずに理由を出して終える（「テスト代表の行がありません。先に npm run fixtures:load を流してください」など）
   - 探し方：名前で取ってから、メールはプログラムで小文字にして比べる（土台の `remove-ceo.mjs` と同じ。`ilike` は `_` を「任意の1文字」として扱うので使わない）
3. その1行の分だけ、権限・MGR の担当・所属を消す。消すときは必ず `.eq('member_id', テスト代表の id)`（MGR の担当は `.eq('mgr_member_id', テスト代表の id)`）で絞る。id が取れていなければ何もしない。ほかの人の行は触らない
   - 権限の表の `granted_by`・`revoked_by` と、MGR の担当の `assigned_by` に、テスト代表の id が入っている行（ほかの人の行）は**直さない**。名簿の行は消さないので、参照は切れない（土台の `remove-ceo.mjs` は名簿の行を消すので空に直しているが、ここでは要らない）
4. 役割を変え、表のとおりに所属・担当・権限を足す
5. どの段階でもエラーを確かめ、エラーなら「切り替えられなかった：〈どの段階か〉：〈error.message〉」と出して、終了コード1で終える。エラーの `details`・`hint`・行の中身は出さない（id が入ることがあるため）。途中で止まったときは、同じコマンドを流し直せば直る（毎回「消してから足す」ため）と、報告書の本人の手順に書く
6. 終わったら「テスト代表を〈日本語の役割。例：架空チームAのリーダー〉に切り替えました。画面を読み込み直すか、ログインし直してください」と出す。メールアドレス・鍵・id は表示しない

### 安全の決まり（2026-10-28 本人の選択）
- 表を足すときは、マイグレーションの中で RLS（行ごとの読み書きの決まり）をオンにする（`alter table ... enable row level security` を明示。自動の設定に頼らない）
- 表ごとの許可（GRANT）をマイグレーションに明示する。`authenticated` は必要な操作だけ（行の範囲は RLS で絞る）、`service_role` は守りのテストのため読み書きと削除、`anon`（ログインしていない人）には何も許可しない
- `service_role` の鍵と、表を流し込むための接続の文字（`SUPABASE_DB_URL`）は画面のコード（`src/`）で使わない。`VITE_` を付けた名前にしない（`VITE_` の付いた値は画面に埋め込まれ、だれでも見られるため）
- 表や権限を変えた計画では、報告書に「Security Advisor の確認が要る」と書く（Supabase の管理画面は本人のアカウントでしか開けない。本人が開いて写しを送り、Claude Code がレビューで確かめる）

- 守りのテストを変更・削除・スキップしない。通らないときはコードを直す。直せなければ止めて報告する

### 数値
