### CSV の読み方
- 先頭の BOM（見えない印の文字 U+FEFF）を外してから読む。文字コードは UTF-8 だけ（Shift_JIS は「止める理由」）
- 引用符（`"`）で囲んだ欄は、中の改行・カンマ・`""`（引用符そのもの）をそのまま読む（ライブラリを足さず、自分で読む関数を作り、テストする）
- 見出しの行：上の見出しが**前から順に**すべて並んでいる行を見出しとする（後ろに空の列や「列1」などの列が続いてもよい）。見出しより上の行は読まない。見出しと同じ中身の行は飛ばす
- 日付：`YYYY/M/D`・`YYYY-M-D`・`YYYY年M月D日`（時刻がついていても日付だけを使う）と、Excel の日付の数（30000〜60000 の整数。1899-12-30 から数えた日）を読む。年のない日付（`9/14` など）・範囲（`7/27~7/31`）・ほかの形は「止める理由」（本人が Excel で日付の表示を年つきに変えて保存し直す）
- 時間：数（分）、`20分`、`0:15`（時:分）を読む。空や読めないときは空（過去の記録は時間を空にしてよい）
- 名前：「、」「,」「・」「／」で区切られていれば複数人。前後の空白と、名前の後ろの全角のかっこ（ふりがな）は外す
- 〇△×：`〇`（U+3007）・`○`（U+25CB）・`◯`（U+25EF）→ `o`、`△` → `d`、`×`・`✕`・`x`・`X` → `x`。ほかの文字や長い文は印にせず、元の行にだけ残す

### 外して進む行と、取り込みを止める理由
| 外して進む（下見に理由と件数を出し、ほかの行は入れる） | 止める（1つでもあれば取り込まない。下見に出す） |
|---|---|
| 中身が空の行（形A：気が付いた内容・指導内容・今後の指導がすべて空。形B・C：日付・名前・詳細がすべて空。形C の FIX：詳細・引継ぎ事項・実践結果がすべて空）、名前が「テスト」の行、同じファイルの中で見出しから後ろの値がすべて同じ行の2回目以降、見出しの繰り返しの行 | 読めない日付、対応表にない名前、対応表のメールが名簿にない、上司・実行者・社員・名前が空、内容・方法が振り分けの表にない、部下メモのテーマが一覧にない（項目が空なら止めない）、一覧に「指摘・指導」の種類がない・同じ名前の一覧が2つある、対応表に同じ組（元の名前・上席か対象か）が2行ある、UTF-8 で読めない |

### 表の直し（マイグレーション）
新しく作る関数とトリガーの関数は、どれも `security definer`・`set search_path = ''` にし、`public, anon, authenticated` から実行の許可を外す。**過去の記録を止めるトリガーは、ログインした人（`auth.role() = 'authenticated'`）のときだけ止める**（管理用の鍵・マイグレーション・SQL エディタは通す。あとで過去の記録を直すマイグレーションが流れるように）。止めるときはエラーにし、文に `legacy` を入れる。
1. **ロープレの記録**：`theme_id` と `time_slot` の「空にできない」を外し、`check (is_legacy or (theme_id is not null and time_slot is not null))` を足す。今の「送ったときは今日直した点・時間・合格ラインの〇△×が必須」の決まり（`create table` の中の名前のない check。Postgres が付けた名前は `roleplays_check`）を `drop constraint roleplays_check`（`if exists` を付けない。名前が違えば流し込みが止まって気づける）で外し、`is_legacy` の行は除く形で足し直す
2. **部下メモ**：今の「送ったときはテーマ・種類・気づいた内容か指導した内容が必須」の決まり（`subordinate_memos_check`）を同じく `if exists` なしで外し、`is_legacy` の行ではテーマ・種類を空でよい形で足し直す（気づいた内容か指導した内容のどちらかは、過去の記録でも必須のまま）
3. **研修の記録**：`seminars` に `is_legacy boolean not null default false` と `legacy_source jsonb` を足す。ログインした人は、追加で `is_legacy` を真にしたり `legacy_source` を入れたりできず、変更でも2つを変えられない（今の研修をあとから過去の記録にすることも、元の行だけを入れることもできない）
4. **過去の記録はだれも直せない・消せない**（2026-11-09 本人の選択）：ログインした人は、`is_legacy` が真の行を変えられない（`hidden_at` を入れる・見えなくすることも含む）。対象：`roleplays`・`subordinate_memos`・`seminars`、過去の部下メモの対象者（`subordinate_memo_targets` の追加・変更）、過去の研修の参加者（`seminar_members` の追加・変更）。管理用の鍵では消せる（取り込み直しと架空データの片づけのため）
5. 読む決まりは変えない（過去の記録も、今の記録と同じ人が読める。部下メモは本人に見せない）

### 取り込みの道具（`scripts/legacy-import/`。管理用の鍵で Supabase につなぐ。`src/` からは使わない）
- 共通：`.env` の `SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` でつなぐ。最初に、つなぐ先のホスト名だけを出す
- **画面（ターミナル）に実名や本文を出さない**：ファイルは「ファイル1（形A）」のように番号と形で呼ぶ（番号とファイル名の対応は `--out` のファイルにだけ書く）。対応表にない名前の一覧・合わない行の詳しい中身は、`--out 〈フォルダ〉` で指定したフォルダのファイルにだけ書き出す（本物は `samples/legacy-import/` を指定する。`--out` がなければ件数だけを出す）。データベースのエラーは `code` と `message` だけを出す（`details`・`hint` と行の中身は出さない。`details` には行の中身が入るため）
- `npm run legacy:preview -- --dir 〈CSV のフォルダ〉 --names 〈対応表〉 [--out 〈フォルダ〉]`：CSV を読み、振り分け・名前の結び・外す行・止める理由を計算して、ファイルごと・形ごとの件数（入る部下メモ・ロープレ・研修・研修の参加者、外す行と理由ごと、止める理由ごと、もう入っている）を出す。データベースには読むだけ（名簿・一覧・もう入っている記録）
- `npm run legacy:import -- --dir … --names … --expect-host 〈入れる先のホスト名〉 --yes [--out …]`：`--expect-host` が今のつなぐ先と同じでなければ止める（本番と開発の取り違えを防ぐ）。`--yes` がなければ止める。下見と同じ計算をし、止める理由が1つでもあれば入れない。なければ入れる（外す行は入れず件数を出す）
- `npm run legacy:remove -- --file 〈ファイル名〉 --expect-host 〈ホスト名〉 --yes`：`legacy_source` の `file` がそのファイル名の過去の記録（部下メモと対象者・ロープレ・研修と参加者）を消す（取り込み直しのため）。消した件数を出す
- 計算（CSV の読み取り・見出しの検出・日付・時間・名前の分け方・〇△×・外す行・止める理由・振り分け・重なりの見分け・画面に出す文の組み立て）は、データベースに頼らない関数にして `tests/legacy-import/` でテストする。テストで、画面に出す文に名前・本文が入らないことも確かめる

### 架空の過去データ（`fixtures/legacy/`）
- `fixtures/legacy/clean/`：取り込める CSV。形A を2ファイル、形B、形C を1ファイルずつ。各10〜20行。外して進む行の例（中身が空・「テスト」・同じ行の2回目・見出しの繰り返し）、研修・FIX・複数人の行・〇△×（3種類の〇を含む）・「今後の指導」・形Cの上の2行・引用符の中の改行とカンマ・BOM つきのファイルを入れる。止める行は入れない
- `fixtures/legacy/errors/`：止める理由の例（読めない日付・年のない日付・対応表にない名前・空の上司・振り分けの表にない内容）だけの CSV。テストで使い、取り込まない
- 名前：土台の架空の人。同じ人に2つの書き方（例：「メンバーA」と「メンA」）と、上席と対象で同じ書き方になる架空の例（例：「架空イトウ」を上席のリーダーAと対象のメンバーBの両方に）を入れ、対応表 `fixtures/legacy/names.csv` で「上席か対象か」で結び分ける
- `fixtures:legacy:load` は `fixtures/legacy/clean/` だけを、`--expect-host` を今のつなぐ先にして取り込む（下見の件数を出してから）。入れる順は 土台（`fixtures:load`）→ 部下メモ（`fixtures:memo:load`。一覧のテーマ・種類が要る）→ 過去の記録。`fixtures:legacy:remove` は `fixtures/legacy/clean/` の各ファイル名で `legacy:remove` と同じ消し方をする。消す順は、過去の記録が先（`fixtures:memo:remove`・`fixtures:remove` より前。一覧の行を参照しているため）
