## 1. 目的（なぜやるか）
新しい言い方を早くチームで試し（リーダーが試行中にする）、会社の標準は責任を持つ人が決める（トーク責任者が標準にする）流れを画面で回せるようにする。研修は1回に何人も参加するので、参加者ごとに記録し、本人もあとで見られるようにする。

## 2. やること
1. トーク一覧の画面（左メニューの「トーク一覧」）
   - 返し（`OUT-`）とスクリプト（`SC-`）を、場面・業種・リストの種類（一覧 `masters` の `scene`・`industry`・`list_type`。`is_active` が偽のものは選ぶ欄に出さない）と、種類（返し／スクリプト）・状態（確認待ち／試行中／標準）で絞り込んで見る
   - 見える範囲はデータベースが決める：名簿にいる人は試行中と標準。確認待ちは、作った人・そのチームのリーダーと担当MGR・トーク責任者・代表
   - 練習回数と合格率：ロープレの記録（`roleplays.used_talk_id`）から数える。数えるのは、送った記録（`submitted_at` あり）で見えなくしていない（`hidden_at` が空）ものだけ（書きかけは数えない）。練習回数＝その記録の数、合格率＝合格ラインが○の数 ÷ 合格ラインが入っている数（入っている数が0なら「－」）。記録は役割どおりにしか読めないので、**見る人が読める記録の範囲で数え、「あなたが見られる記録から数えています」と添える**（2026-11-04 本人の選択。全社の数を全員に見せるかは、使ってみてから決める）
2. 確認の2段階（ボタンは押せる人にだけ出す。データベースでも絞られている）
   - 確認待ち → 試行中：そのチームのリーダーと担当MGR。チームなしの確認待ちは代表（代表には、チームつきの確認待ちのボタンを出さない。データベースでも断る）
   - 試行中 → 標準：トーク責任者の権限がある人だけ
   - この2つのほかの動き（飛ばす・戻す）のボタンは出さない（データベースでもできない）
3. トークを足す・直す
   - 「トークを足す」ボタンは、リーダー・MGR・トーク責任者・代表にだけ出す（2026-11-04 本人の選択。メンバーは②のロープレを書く画面の「新しい言い方」から確認待ちで入れる）。足すと必ず「確認待ち」で入る（トーク責任者でも、最初から標準にはできない）
   - チーム：リーダー・メンバーは自分の今のチーム、MGR は担当しているチームから選ぶ、代表はチームなし（全体）か、どのチームでも選べる（2026-11-04 本人の選択。`shared/viewer.ts` の `selectableTalkTeams`）。直すときにチームを変える場合も、同じ範囲から選ぶ（チームを変えないときは今のまま。トーク責任者がほかのチームのトークを直すときなど、今のチームが選べる範囲にないことがある）。「トークを足す」ボタンは  が真の人にだけ出す（選べるチームが1つもない人には出さない）
   トークのコードの付け方（②③で同じ）：`OUT-`（返し）か `SC-`（スクリプト）＋日付8桁（日本時間。例：`20261104`）＋ `-` ＋ `crypto.randomUUID()` の頭4文字を大文字にしたもの（例：`OUT-20261104-3F9A`）。番号から並べ順を作らない（並べるのは場面・状態・コードの文字の順）。架空データの `OUT-FIXTURE-001` の形もそのまま表示する
   - 場面・業種・リストの種類は一覧（masters）から選ぶ
   - 直す（見えなくする `hidden_at` を含む）：作った人は確認待ちの間だけ。そのチームのリーダーと担当MGR・トーク責任者・代表は、いつでも
4. 研修の記録の画面（左メニューの「研修の記録」）
   - 日付・テーマ・講師・時間・内容と、参加者（複数選ぶ）
   - 研修を足すのはリーダー・MGR。直す・見えなくするのは、その研修を作った人だけ
   - 参加者を足す・外すのは、その研修を作った人だけ。外すときは `seminar_members.removed_at` を入れる（削除はしない）。外した人を戻すときは、足し直さずに（同じ組の行がすでにあるので断られる）、その行の `removed_at` を空にする（update）。外した行も含めて読むときは、`shared/` の `fetchSeminarMembers`（外した行を除く）ではなく、自分のフォルダの中で読む
   - 参加者の候補：作る人が名簿で読める人のうち、退職日を過ぎていない人
   - 見える範囲：参加した本人（外されていない人）は自分が参加した研修、リーダー・MGR・代表はすべて
5. テスト：練習回数と合格率の数え方は、計算だけの部品（データベースに触らない関数）に分けて、架空のデータでテストする（`tests/roleplay/talks/` に置く）
