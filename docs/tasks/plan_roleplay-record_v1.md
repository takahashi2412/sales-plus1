## 1. 目的（なぜやるか）
リーダーが、今の Excel の代わりに、ロープレを1回1テーマで記録し、練習中のテーマを卒業まで追えるようにする。毎回書くのは「今日直した点」1つだけにして、ほかは選ぶか自動にする。

## 2. やること
1. ロープレを書く画面：自動＝日付・実行者・時間帯・内容（アポ／営業）・練習中のテーマ・前回の宿題。選ぶ＝課員・使ったトーク・時間・宿題の○△×・くり返し回数・合格ラインの○△×・次回の宿題。書く＝今日直した点（必須・1つ）、申し送り・新しい言い方（任意）
   - 新しい言い方を書いたら、トーク一覧に「確認待ち」で入る（③の画面がなくても、表に入ればよい）
   - 入口：左メニュー。対象者が入った状態で開く入口（カルテの「この人に書く」）は、カルテ第1版でつなぐ
2. ロープレの一覧：人・期間・テーマで絞り込み。本人は自分の分だけ
3. テーマ表の画面：課員ごとの練習中のテーマ（アポと営業で1つずつまで）・開始日・合格ライン・状態
4. 卒業の知らせ：○が設定値の回数（初めは2回）続いたら「卒業の候補」を、確認までの日数（初めは14日）がたったら「確認のロープレ」を、この画面の上に件数つきで出す。上席（リーダー・担当MGR・代表）が卒業にする。確認で×なら上席が練習中に戻す（2026-11-04 本人の選択）
   - 注意の2つ（30分を超えたら確認、14日以上練習中なら注意）も出す。数字は設定値から読む
5. 書きかけは自動で下書き保存し、「送る」まで上席に見えない（設計書9章「書く画面の決まり」）
6. テスト：卒業の候補・確認の日・注意の判定は、計算だけの部品に分けて、架空のデータでテストする

### 安全の決まり（2026-10-28 本人の選択）
- 表を足すときは、マイグレーションの中で RLS（行ごとの読み書きの決まり）をオンにする（`alter table ... enable row level security` を明示。自動の設定に頼らない）
- 表ごとの許可（GRANT）をマイグレーションに明示する。`authenticated` は必要な操作だけ（行の範囲は RLS で絞る）、`service_role` は守りのテストのため読み書きと削除、`anon`（ログインしていない人）には何も許可しない
- `service_role` の鍵と、表を流し込むための接続の文字（`SUPABASE_DB_URL`）は画面のコード（`src/`）で使わない。`VITE_` を付けた名前にしない（`VITE_` の付いた値は画面に埋め込まれ、だれでも見られるため）
- 表や権限を変えた計画では、報告書に「Security Advisor の確認が要る」と書く（Supabase の管理画面は本人のアカウントでしか開けない。本人が開いて写しを送り、Claude Code がレビューで確かめる）
