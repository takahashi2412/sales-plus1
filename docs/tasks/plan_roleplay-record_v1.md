## 1. 目的（なぜやるか）
リーダーが、今の Excel の代わりに、ロープレを1回1テーマで記録し、練習中のテーマを卒業まで追えるようにする。毎回書くのは「今日直した点」1つだけにして、ほかは選ぶか自動にする。

## 2. やること
1. ロープレを書く画面
   - 自動＝日付・実行者（ログインしている人）・時間帯（`time_slot`。例：`'10'`＝10時台）・内容（アポ／営業。課員に練習中のテーマがあればその内容、なければアポ。選んで変えられる）・練習中のテーマ・前回の宿題
   - 練習中のテーマが読めない（メンバーが実行者のときは、ほかの人のテーマ表は読めない）・ないときは、テーマ一覧（`roleplay_themes` の `is_active` が真で、内容が同じもの）から選ぶ。前回の宿題は、読める記録のうち、その課員のいちばん新しい送った記録の「次回の宿題」。なければ空
   - 選ぶ＝課員・使ったトーク（`used_talk_id`。空でよい）・時間（分）・宿題の○△×・くり返し回数・合格ラインの○△×・次回の宿題
   - 書く＝今日直した点（送るときは必須・1つ）、申し送り・新しい言い方（任意）
   - 課員の選ぶ欄に出すのは、ログインしている人が書ける人だけ（`shared/viewer.ts` の `fetchWritableMembers`）：リーダー・メンバーは今同じチームの人、MGR は担当しているチームの人、代表は全員。どれも自分と、退職日を過ぎた人を除く（データベースも同じ範囲で絞っている。管理者の権限では広げない。実行者と課員は別の人）
   - 新しい言い方：書く欄は「相手の言葉」と「言い方」の2つ（任意）。**送るときに1回だけ**、トーク一覧（`talks`）に「確認待ち」（`status = 'pending'`、`created_by` は自分）で1行足す（下書きの保存では足さない）。相手の言葉は `their_words`、言い方は `wording` に入れ、場面・業種・リストの種類は空のまま。足したトークを、その記録の `used_talk_id` につなぐ（使ったトークを選んでいないとき）。チームは、メンバー・リーダーは自分の今のチーム、MGR と代表は課員の今のチーム（課員にチームがないときは空。データベースでは代表だけが通る）（③の画面がなくても、表に入ればよい）
   トークのコードの付け方（②③で同じ）：`OUT-`（返し）か `SC-`（スクリプト）＋日付8桁（日本時間。例：`20261104`）＋ `-` ＋ `crypto.randomUUID()` の頭4文字を大文字にしたもの（例：`OUT-20261104-3F9A`）。番号から並べ順を作らない（並べるのは場面・状態・コードの文字の順）。架空データの `OUT-FIXTURE-001` の形もそのまま表示する
   - 入口：左メニューの「ロープレ」。対象者が入った状態で開く入口（カルテの「この人に書く」）は、カルテ第1版でつなぐ
2. ロープレの一覧：人・期間・テーマで絞り込み。読める範囲はデータベースが決める（本人は自分の送った分、上席は担当の人の送った分、書いた人は自分が書いた分すべて＝書きかけも）。並べるのは日付と時間帯（時間帯は数として並べる。`'9'` が `'10'` より前）
3. テーマ表の画面（左メニューの「テーマ表」）：課員ごとの練習中のテーマ（アポと営業で1つずつまで）・開始日・合格ライン・状態。テーマを足す・直すのは上席（リーダー・担当MGR・代表）だけ。ボタンも上席にだけ出す。自分自身の行には、足す・卒業・戻すのボタンを出さない（自分の上席が行う。データベースでも断る）。ボタンを出すかは `shared/viewer.ts` の `canSuperviseMember(viewer, { id, teamId })` で決める
   - 練習中はアポと営業で1つずつまで（データベースの一意の決まり）。同じ内容で練習中のテーマがあるときは、「足す」「練習中に戻す」のボタンを出さず、理由を知らせの枠に出す
4. 卒業の知らせ（テーマ表の画面の上に件数つきで出す）
   - 卒業の候補：そのテーマの開始日（`started_on`）以後の、送った記録（日付・時間帯の順）で、合格ラインの○が `roleplay_graduate_count`（初め 2）回続いたら
   - 卒業にするときは、`graduated_on` に今日、`check_on` に今日＋`roleplay_check_days`（初め 14）日を入れる
   - 確認のロープレ：`check_on` の日になったら知らせる。`check_on` 以後に、そのテーマで送った記録があれば、知らせを消す（○なら卒業のまま、×なら上席が練習中に戻す）
   - 卒業にする・練習中に戻すのは上席だけ（課員本人や、実行者のメンバーはできない。2026-11-04 本人の選択）。ボタンは上席にだけ出す
   - 注意の2つ：1回のロープレが `roleplay_alert_minutes`（初め 30）分を超えたら確認、`roleplay_alert_days`（初め 14）日以上同じテーマが練習中なら注意
   - 数字は設定値から読む（①の `src/features/roleplay/shared/` の `fetchRoleplaySettings` を使う。設定値の行がないときに使う予備の数字は、①の `DEFAULT_ROLEPLAY_SETTINGS` のまま。画面のコードに数字を直接書かない）
5. 書きかけ：課員・内容・テーマ・時間帯がそろったら、最初の1行を入れ（この4つは空にできない列のため）、そのあとは自動で下書き保存する（`submitted_at` が空）。「送る」まで上席に見えない（設計書9章「書く画面の決まり」）。書きかけの間は、時間と合格ラインの○△×が空でもよい。送るとき（`submitted_at` を入れるとき）は、今日直した点・時間・合格ラインの○△×の3つがそろっていないと送れない（データベースでも確かめている）。消す＝`hidden_at` を入れる（書いた人だけ）。送ったあとも、書いた人は中身を直せる（設計書「書く画面の決まり」）。ただし、送った記録を書きかけに戻す（`submitted_at` を空にする）操作は出さない
6. テスト：卒業の候補・確認の日・注意の判定は、計算だけの部品（データベースに触らない関数）に分けて、架空のデータでテストする（`tests/roleplay/record/` に置く）

### 安全の決まり（2026-10-28 本人の選択）
- 表を足すときは、マイグレーションの中で RLS（行ごとの読み書きの決まり）をオンにする（`alter table ... enable row level security` を明示。自動の設定に頼らない）
- 表ごとの許可（GRANT）をマイグレーションに明示する。`authenticated` は必要な操作だけ（行の範囲は RLS で絞る）、`service_role` は守りのテストのため読み書きと削除、`anon`（ログインしていない人）には何も許可しない
- `service_role` の鍵と、表を流し込むための接続の文字（`SUPABASE_DB_URL`）は画面のコード（`src/`）で使わない。`VITE_` を付けた名前にしない（`VITE_` の付いた値は画面に埋め込まれ、だれでも見られるため）
