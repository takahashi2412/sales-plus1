## 2. やること

1. 計算の部品（`src/features/admin/shared/`。画面やデータベースに頼らない関数にする）とテスト（`tests/admin/`）
   - 名簿の CSV の読み取り：文字コードは、先頭に BOM があれば UTF-8、なければ Shift_JIS（`TextDecoder('shift_jis')`。Excel の「CSV UTF-8」と「CSV（コンマ区切り）」の両方を読めるように）。1行目は見出し：`名前,メール,役割,営業に出る,入社日,チーム,拠点,所属の開始日`。役割は `メンバー／リーダー／MGR`（代表は取り込みでは入れられない。2026-11-07 本人の選択：代表の役割を変えられるのは代表だけ）、営業に出るは `出る／出ない`、日付は `YYYY-MM-DD` か `YYYY/MM/DD`。必須の欄：名前・メール・役割・営業に出る・入社日はいつも。チーム・拠点・所属の開始日は、メンバーとリーダーは必須、MGR は空にする（MGR の担当は取り込みのあとに画面で設定する）
   - 取り込む前の確かめ（行ごとに、合わない理由を全部出す）：必須の欄が空、メールの形、同じファイルの中でメールが重なる、名簿にもう同じメールがいる（大文字・小文字を区別しない）、役割・営業に出るの言葉が違う、役割が「代表」、日付が読めない、所属の開始日が入社日より前、チームが名簿にない（「新しいチームとして作る」を選べる）、メンバー・リーダーなのにチーム・拠点・所属の開始日が空、MGR なのにチーム・拠点・所属の開始日が入っている
   - 異動の計画：新しい所属の開始日を入れると、今の所属の終わりの日を「開始日の前の日」にし、新しい所属の行を足す（上書きしない。設計書9章）。開始日が今の所属の開始日以前ならエラー
   - 退職の計画：退職日を入れると、①持っている権限（管理者・トーク責任者）を外す（`revoked_at`）→ ②今の所属の終わりの日を退職日にし、MGR の担当があれば終わりの日を退職日にする → ③名簿の退職日を入れる、の順に行う（最後の1人の管理者を退職させようとすると、データベースが①で止める）
   - 権限の計画：与える（同じ人・同じ種類の有効な権限がもうあれば足さない）・外す
   - データベースのエラーの見分け：エラーの文に `last admin` が入っていれば「最後の1人の管理者は外せません。先にほかの人に管理者の権限を与えてください」、そのほかは「この操作はできません（理由：…）」にする関数。テストで両方を確かめる
   - 役割の選び方：見る人が代表（で管理者の権限がある）でなければ、役割の選べる値に「代表」を出さず、代表の行の役割は変えられないようにする（データベースも止める）
2. 名簿の管理の画面（`src/features/admin/members/`。入口 `#/admin-members` は①でできている。管理者の権限がある人だけ）
   - 一覧：名前・役割・今のチーム・拠点・入社日・営業に出る・退職日・MGR の担当。チーム・役割・在籍／退職で絞り込める
   - 1人を足す：上の CSV と同じ欄。足したあと、その人が Microsoft 365 で初めてログインしたときに、メールで名簿の行と結ばれる（今の土台の仕組み）ことを画面に1行で書く
   - 1人を直す：名前・メール・役割・営業に出る・入社日（役割の「代表」は上の「役割の選び方」のとおり）。営業に出るを変えたときは「翌月の目標から反映されます（今月の目標はそのまま）」と出す
   - 異動・退職：上の計画どおりに、所属の履歴に足す・閉じる。所属の履歴を一覧で見られる
   - MGR の担当：MGR ごとに、担当するチームと期間（開始日・終わりの日）を足す・終える（担当は期間つき。上書きしない）
   - チーム：チームを足す・名前を変える（消さない）
   - 一括取り込み：ひな形（下の「ひな形」）を画面から取り出せる → CSV を選ぶ → 1の確かめの結果を表で出す（合わない行は理由つき） → 合わない行がなくなったら「取り込む」 → 名簿・所属（・新しいチーム）を入れる。取り込んだ件数を出す
3. 権限の管理の画面（`src/features/admin/permissions/`。入口 `#/admin-permissions` は①でできている。管理者の権限がある人と代表）
   - 今の権限の一覧：人ごとに、管理者・トーク責任者を持っているか、与えた人・与えた日
   - 与える：人と種類を選んで与える（`permissions` に行を足す。`granted_by` は自分）
   - 外す：`revoked_at` と `revoked_by` を入れる（行は消さない）。最後の1人の管理者を外そうとするとデータベースが止めるので、そのときは「最後の1人の管理者は外せません。先にほかの人に管理者の権限を与えてください」と出す（2026-11-07 本人の選択）
   - 前の権限（外したもの）の一覧も見られる
   - 自分の管理者の権限を外すときは、確かめの1文（「外すと、この画面と名簿の管理は使えなくなります」）を出す
4. ひな形：`public/templates/members_template.csv` を作る（文字コードは BOM つきの UTF-8。BOM がないと、日本語の Excel で見出しが文字化けするため。見出しの1行と、架空の例を2行だけ。例は「架空メンバー」「example.test」の名前とメールにする。本物の名前は入れない）

### 安全の決まり（2026-10-28 本人の選択）

- 表ごとの許可（GRANT）をマイグレーションに明示する。`authenticated` は必要な操作だけ（行の範囲は RLS で絞る）、`service_role` は守りのテストのため読み書きと削除、`anon`（ログインしていない人）には何も許可しない
- `service_role` の鍵と、表を流し込むための接続の文字（`SUPABASE_DB_URL`）は画面のコード（`src/`）で使わない。`VITE_` を付けた名前にしない（`VITE_` の付いた値は画面に埋め込まれ、だれでも見られるため）
